# Casos de Uso

Casos de uso transformam requisitos abstratos em fluxos reais e testáveis.

Eles fazem parte da documentação canônica.

## Regras

- devem ser autossuficientes;
- não dependem de implementações externas;
- descrevem comportamento, dados, permissões e critérios de aceite;
- não devem hardcodar no core regras que pertencem somente ao caso;
- funcionam como base de homologação e regressão.
